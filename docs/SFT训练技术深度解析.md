## SFT 的本质：从续写到对话的范式转变

### 预训练模型的"续写本能"

要理解 SFT 的必要性，首先需要理解预训练模型的行为模式。GPT 类模型的预训练目标是"预测下一个 token"——给定上文，模型学习预测最可能出现的下一个词。这个看似简单的目标，让模型在海量文本中学会了语言的统计规律。

但这里存在一个微妙的问题：**预测最可能的续写，与给出有帮助的回答，是两个本质不同的任务**。

考虑这个输入："请解释什么是机器学习"。预训练模型可能给出的续写包括："？机器学习是..."（像在朗读问题）、"，这是一个重要的..."（像在接话）、或 "的定义在学术界..."（像在写论文）。这些续写从语言统计的角度都是合理的，但没有一个真正在"回答问题"。

这就是 SFT 要解决的核心问题：**将模型从"续写者"转变为"对话者"**。

### 从任务微调到指令微调的演进

SFT 的发展经历了三个重要阶段，每个阶段都代表着对"如何让模型听从指令"这一问题的更深理解。

**第一阶段（2018-2019）：任务特定微调**。在 BERT 时代，研究者为每个下游任务（如情感分类、命名实体识别）单独微调一个模型。这种方法的问题在于，模型学到的是"如何完成特定任务"，而不是"如何理解并执行通用指令"。

**第二阶段（2020-2021）：统一的文本生成框架**。T5 模型提出了革命性的理念——将所有 NLP 任务统一为"文本到文本"的格式。翻译任务变成"translate English to French: The house is big"，情感分类变成"classify sentiment: This movie is great"。这种统一格式让模型开始学习"根据前缀指令决定行为"，是指令微调的雏形。

**第三阶段（2022-至今）：大规模指令微调**。InstructGPT 的成功标志着 SFT 技术的成熟。关键创新在于：使用人类编写的高质量指令-回答对进行训练，并引入人类反馈（RLHF）进一步优化。这个阶段的模型不再是"学会某些任务"，而是真正"学会如何有帮助地回答问题"。

理解了这个演进脉络，我们就能更好地理解 SFT 的核心设计决策——特别是下文要讨论的 Loss Mask 机制。

## Loss Mask：精准控制学习信号的艺术

在 SFT 的所有技术细节中，Loss Mask 机制是最具深意的设计之一。它决定了模型从训练数据中"学什么"与"不学什么"，直接影响最终的对话能力。

### 为什么不能对整个序列计算损失？

考虑一个典型的 SFT 训练样本，包含用户问题和助手回答。一个朴素的想法是：既然整个序列都是有意义的文本，为什么不对所有 token 计算损失呢？

这种做法存在三个层面的问题：

**学习目标的错位**。模型在推理时的任务是"给定用户输入，生成回答"，而不是"生成用户输入"。如果在用户问题的 token 上也计算损失，模型实际上在学习一个它永远不需要执行的技能——这是浪费。

**学习信号的稀释**。假设一个样本中用户问题占 20% 的 token，助手回答占 80%。如果等权重计算损失，问题部分的每个 token 获得了与回答部分相同的重要性。但我们真正关心的是模型"怎么回答"，而非"怎么提问"。

**梯度信号的干扰**。更微妙的问题在于，用户问题往往风格多样（可能包含口语、错别字、不完整的句子），而助手回答需要规范、准确。如果两部分混合训练，模型可能学到错误的风格倾向。

### Loss Mask 的设计哲学

Loss Mask 的核心思想很简单：**只在我们希望模型学习的位置计算损失**。具体实现时，为每个 token 分配一个 0 或 1 的标记：1 表示该位置参与损失计算，0 表示忽略。

在 SFT 场景中，典型的 Mask 策略是：用户输入部分标记为 0，助手回答部分标记为 1，填充（padding）部分也标记为 0。这样，模型只会从"如何生成好的回答"中学习，而不会被其他内容干扰。

### 归一化策略的重要性

一个容易被忽视的细节是损失的归一化方式。考虑两个 batch：A 包含 800 个有效 token（需要学习的位置），B 包含 400 个有效 token。如果简单地将总损失除以序列长度，B 的平均损失会被人为放大——因为同样的序列长度中，B 的学习信号更集中。

正确的做法是**除以有效 token 数**，而非序列总长度。这确保了损失值始终代表"每个有效 token 的平均预测难度"，使不同 batch 的损失值具有可比性，也让训练动态更加稳定。

这个看似微小的设计选择，实际上体现了一个重要原则：**训练指标应该真实反映我们关心的目标**。Loss Mask 让我们只关注回答质量，归一化策略让这个关注度的衡量标准保持一致。

## 学习率的智慧：为什么 Warmup 不可或缺

学习率调度是深度学习中最核心的超参数决策之一。在 SFT 训练中，Warmup + 余弦退火（Cosine Decay）的组合已成为事实上的标准，这背后有深刻的优化理论支撑。

### Warmup：给优化过程一个稳定的起点

训练开始时，模型参数处于随机初始化状态（或预训练后的状态）。此时的梯度方向具有高度不确定性——它反映的是当前 batch 的统计特性，而非真实的优化方向。

如果在这个阶段使用较大的学习率，会产生几个问题：

**参数剧烈震荡**。大学习率意味着参数在每一步都有大幅度更新。在梯度不稳定的阶段，这种大幅更新可能导致模型在参数空间中"乱跳"，难以找到好的下降方向。

**损失尖峰**。实践中经常观察到，不使用 Warmup 的训练在前几十步会出现损失突然飙升的现象。这是因为某些异常梯度导致参数更新到了损失曲面的"悬崖"边缘。

**不良初始化**。更严重的情况是，早期的不稳定更新可能将模型推向难以逃脱的不良区域（如某些参数接近饱和），即使后续稳定下来，也难以恢复最优性能。

Warmup 的解决方案很直接：**让学习率从零开始线性增长到目标值**。这给了优化器一个"热身"期，在模型还不稳定时小心翼翼地探索，逐渐建立起正确的优化方向后再加速前进。

### 余弦退火：优雅地收敛

Warmup 结束后，学习率进入余弦退火阶段。这种衰减方式有一个独特的形状：**初期和末期衰减缓慢，中期衰减较快**。

这个形状与训练动态非常匹配：

**训练初期**，模型还在"探索"参数空间，需要保持较高的学习率以跨越可能存在的局部障碍。余弦曲线在这个阶段几乎是平的，学习率维持在高位。

**训练中期**，模型已经找到了大致正确的方向，需要逐渐聚焦。余弦曲线在这个阶段快速下降，让模型从"粗调"过渡到"细调"。

**训练后期**，模型接近最优点，需要极其谨慎地微调。余弦曲线在这个阶段趋于平缓，避免过大的更新导致跳出良好区域。

相比之下，线性衰减在初期下降过快，可能过早限制了模型的探索能力；阶梯衰减在突变点会造成训练动态的剧烈变化，引入不必要的不稳定性。

### 参数选择的实践指导

Warmup 步数的选择需要考虑几个因素：

**总训练步数**。经验上，Warmup 占总步数的 1-5% 是合理范围。对于 10000 步的训练，100-500 步 Warmup 通常足够。

**学习率大小**。目标学习率越大，需要越长的 Warmup。因为从零增长到较大值的过程中，梯度的不稳定性更容易暴露。

**模型规模**。更大的模型有更多参数需要协调，通常需要更长的 Warmup 来建立稳定的优化动态。

最终的选择往往需要实验验证，但一个安全的起点是：Warmup 步数设为 min(1000, 总步数 × 1%)。

## 混合精度训练：在速度与精度间起舞

现代 GPU 对低精度运算有专门的硬件加速支持。混合精度训练利用这一特性，在几乎不损失模型质量的前提下，将训练速度提升近一倍。理解其原理，对于高效 SFT 训练至关重要。

### FP16 与 BF16：两种十六位浮点的哲学

标准的神经网络训练使用 FP32（32 位浮点数），它提供约 7 位有效数字和巨大的数值范围。混合精度训练的核心是用 16 位格式替代部分计算，目前有两种主流选择：

**FP16（IEEE 半精度）** 是更早出现的格式。它将 16 位分配给：1 位符号、5 位指数、10 位尾数。这给出约 3-4 位有效数字，但数值范围有限（最大约 65504）。

**BF16（Brain Float 16）** 是 Google 为深度学习专门设计的格式。它采用与 FP32 相同的指数位数（8 位），只压缩尾数（7 位）。这意味着数值范围与 FP32 完全相同，但精度降低到约 2 位有效数字。

两种格式的关键区别在于"范围 vs 精度"的权衡。FP16 选择了更高精度但受限的范围，BF16 选择了完整范围但较低精度。对于深度学习，**范围往往比精度更重要**——梯度可能非常小（如 1e-7），FP16 会将其下溢为零，而 BF16 可以正确表示。

### 梯度缩放：FP16 的救命稻草

FP16 的范围限制带来了一个严重问题：**梯度下溢**。在深层网络中，梯度在反向传播过程中可能变得非常小。当这些小梯度无法被 FP16 表示时，它们会被舍入为零，导致相应参数完全停止更新。

GradScaler（梯度缩放器）是解决这个问题的标准方案，其工作原理巧妙而直接：

**缩放损失**。在反向传播之前，将损失值乘以一个较大的因子（如 65536）。由于梯度与损失成正比，这相当于等比例放大所有梯度。

**反缩放梯度**。在优化器更新参数之前，将梯度除以相同的因子，恢复到原始尺度。

**动态调整**。缩放因子不是固定的。如果检测到梯度溢出（变成无穷大），说明缩放过度，需要减小因子并跳过本次更新；如果连续多步没有溢出，可以尝试增大因子以获得更好的精度。

BF16 由于保持了完整的数值范围，通常不需要 GradScaler——这也是它在新款 GPU（如 A100、H100）上更受青睐的原因之一。

### "混合"的精髓

混合精度之所以叫"混合"，是因为并非所有操作都使用低精度。实践中，计算密集型操作（如矩阵乘法）使用 FP16/BF16 以获得加速，而数值敏感操作（如损失计算、Softmax）保持 FP32 以维持精度。

现代深度学习框架（如 PyTorch 的 autocast）会自动处理这种混合。开发者只需指定一个上下文，框架会在其中智能地选择每个操作的精度。这种自动化大大降低了混合精度训练的门槛，同时保持了接近最优的性能。

## 梯度的驯服：累积与裁剪的平衡术

显存限制和训练稳定性是 SFT 面临的两大工程挑战。梯度累积解决前者，梯度裁剪应对后者。理解这两种技术的原理与配合，是高效稳定训练的关键。

### 梯度累积：以时间换空间

GPU 显存是训练的硬约束。当模型规模或批次大小超过显存容量时，直接增大 batch_size 是不可能的。但小的 batch_size 意味着梯度估计的高方差，可能导致训练不稳定或收敛到次优解。

梯度累积提供了一个优雅的解决方案：**多次前向-反向传播，累积梯度，然后一次性更新参数**。

假设显存只能容纳 batch_size=4，但我们希望模拟 batch_size=16 的效果。梯度累积的做法是：进行 4 次前向-反向传播（每次 batch_size=4），将梯度累加起来，然后执行一次参数更新。从数学上看，累积的梯度等于大 batch 梯度的估计。

这里有一个重要的细节：**损失需要除以累积步数**。因为每次反向传播都会将梯度加到累积器上，不做归一化的话，最终梯度会是期望值的 4 倍，等效于将学习率放大了 4 倍。

梯度累积的代价是训练时间的增加——每次真正的参数更新需要多次前向-反向传播。但这种时间换空间的权衡，在显存受限的场景下是完全值得的。

### 梯度裁剪：稳定性的守护者

深度神经网络训练中，梯度爆炸是一个常见问题。特别是在处理长序列时，梯度通过反向传播层层累积，可能变得极其巨大，导致参数更新失控。

梯度裁剪的思想很直接：**如果梯度"太大"，就按比例缩小它**。关键问题在于如何定义"太大"。

最常用的方法是**全局范数裁剪**：将所有参数的梯度视为一个大向量，计算其 L2 范数（欧几里得长度）。如果范数超过阈值，就等比例缩小所有梯度，使范数恰好等于阈值。

为什么是全局范数而不是逐参数裁剪？逐参数裁剪会改变梯度的相对方向——某些维度被裁剪后，梯度向量不再指向原来的方向。全局范数裁剪保持了方向，只改变步长，这更符合优化的直觉。

阈值的选择通常是 1.0，这是经过广泛验证的经验值。它的含义是：即使遇到最极端的 batch，参数更新的幅度也不会超过正常情况太多。太小的阈值会过度限制学习，太大则无法有效防止爆炸。

### 梯度累积与裁剪的协同

当同时使用梯度累积和梯度裁剪时，执行顺序很重要。正确的流程是：

1. 多次前向-反向传播，累积梯度
2. 对累积后的梯度进行裁剪
3. 执行参数更新
4. 清零梯度

如果在每次小 batch 后就裁剪，等效于对部分梯度多次裁剪，会过度限制总梯度的大小。梯度裁剪应该作用于"最终要用于更新的梯度"，即累积完成后的结果。

## 分布式训练：协同的力量

当单卡无法满足训练需求时，分布式训练成为必然选择。数据并行（Data Parallel）是最常用的分布式策略，PyTorch 的 DistributedDataParallel（DDP）提供了优雅的实现。

### 数据并行的核心思想

数据并行的原理可以用一句话概括：**多个 GPU 各自持有模型的完整副本，处理不同的数据子集，然后同步梯度**。

具体过程是：将训练数据切分成 N 份（N 是 GPU 数量），每个 GPU 在自己的数据子集上执行前向和反向传播，计算出本地梯度。然后，所有 GPU 通过 AllReduce 操作交换梯度，得到平均梯度（等价于在完整 batch 上计算的梯度）。最后，每个 GPU 用相同的平均梯度更新各自的模型副本。

由于使用相同的初始化和相同的梯度，所有 GPU 上的模型始终保持同步——这是数据并行正确工作的关键不变量。

### DDP 的工程优化

PyTorch 的 DDP 相比早期的 DataParallel 有重大改进，主要体现在两个方面：

**多进程架构**。DataParallel 使用单进程多线程，受限于 Python 的 GIL（全局解释器锁），难以实现真正的并行。DDP 使用多进程架构，每个 GPU 对应一个独立的 Python 进程，彻底避免了 GIL 问题。

**梯度分桶通信**。DDP 不会等所有梯度计算完毕才开始通信。它将参数分成多个"桶"，当一个桶的所有梯度准备好后，立即开始该桶的 AllReduce。这实现了计算与通信的重叠，大幅提升了效率。

### 数据切分的保证

在分布式训练中，确保每个 GPU 处理不同的数据至关重要。DistributedSampler 承担了这个职责。它根据总进程数和当前进程编号，自动为每个进程分配互不重叠的数据子集。

一个容易忽略的细节是 **epoch 级别的随机化**。如果每个 epoch 数据顺序相同，不同 GPU 处理的样本组合也会相同，这可能引入不希望的偏差。DistributedSampler 通过 set_epoch 方法，使用 epoch 编号作为随机种子，确保每个 epoch 都有不同且一致的数据分配。

### 主进程与从进程

分布式训练中，某些操作只应该执行一次，比如保存模型、打印日志。如果所有进程都执行，会造成重复输出或文件冲突。

通用的解决方案是指定一个"主进程"（通常是 rank=0 的进程）负责这些操作，其他进程跳过。这需要在代码中添加条件判断，区分是否为主进程后再执行相应逻辑。

## 检查点机制：训练的"存档点"

长时间训练面临各种中断风险：硬件故障、软件崩溃、资源抢占。没有检查点机制，一次中断可能导致数天甚至数周的训练付之东流。

### 完整检查点 vs 推理权重

一个完整的训练检查点需要包含所有恢复训练所需的信息：

**模型参数**是最基本的内容，决定了模型当前的能力。

**优化器状态**对于 Adam 类优化器尤为重要。Adam 维护每个参数的一阶矩（momentum）和二阶矩（variance）估计，这些状态经过数千步积累，包含了丰富的优化历史信息。如果不保存优化器状态，恢复后的训练就像是从头开始优化——需要重新积累动量，可能导致短期内的不稳定。

**训练进度**（如当前 epoch、step）让恢复后的训练能够从正确的位置继续，特别是影响学习率调度这类与步数相关的逻辑。

与完整检查点不同，推理时只需要模型参数。因此，实践中通常同时保存两个版本：完整检查点用于恢复训练，精简的参数文件用于部署推理。后者还可以进一步压缩（如转换为半精度），以减少存储和传输成本。

### 保存频率的权衡

保存检查点并非没有代价。每次保存涉及大量磁盘 I/O，可能需要数十秒甚至数分钟。过于频繁的保存会显著拖慢训练进度。

另一方面，保存间隔过长意味着中断时损失的进度更多。如果每 10 小时保存一次，最坏情况下可能丢失近 10 小时的训练成果。

合理的策略是根据训练规模调整保存频率。一个经验法则是：**确保任何时候最多损失 1-2 小时的训练量**。对于大规模训练，这可能意味着每半小时保存一次；对于小规模实验，每个 epoch 保存一次可能就足够了。

### 恢复的完整性验证

恢复训练时，除了加载检查点，还应该验证恢复是否成功。常见的验证方式包括：

**比较恢复后的损失值**。恢复后第一个 batch 的损失应该与中断前最后记录的损失接近（允许由于数据采样随机性导致的小差异）。

**检查学习率**。如果使用依赖步数的学习率调度，恢复后的学习率应该与中断时一致。

**监控早期训练动态**。恢复后的损失曲线应该平滑延续，而非出现明显的跳变或震荡。

## MoE 架构的特殊挑战：负载均衡之道

混合专家（Mixture of Experts，MoE）是一种通过条件计算提升模型容量的技术。在 MoE 架构中，输入不再经过所有参数，而是由门控网络动态选择部分"专家"进行处理。这带来了容量与计算的解耦，但也引入了独特的训练挑战——负载均衡问题。

### 专家崩溃：赢者通吃的困境

MoE 的理想状态是所有专家被均匀使用，每个专家学习处理不同类型的输入。但实践中经常观察到**专家崩溃**现象：少数专家被压倒性地选中，大多数专家几乎无人问津。

这种现象的根源是**正反馈循环**：

1. 由于随机初始化，某些专家在早期偶然获得较高的选择概率
2. 被选中的专家接收更多梯度信号，能力提升更快
3. 能力更强的专家在后续被选中的概率更高
4. 循环强化，最终形成"赢者通吃"的局面

崩溃的后果是严重的：大量参数闲置浪费，模型实际容量远低于设计容量，MoE 的优势完全丧失。

### 辅助损失：打破正反馈

辅助损失（Auxiliary Loss）是对抗专家崩溃的标准武器。它的核心思想是：**惩罚不均衡的专家使用，强制模型将负载分散到所有专家**。

具体计算方式涉及两个量度：

**专家选择概率**。门控网络对每个专家输出一个"分数"，softmax 后成为选择概率。如果某专家的平均概率远高于 1/N（N 是专家数），说明门控偏向于它。

**专家实际使用频率**。统计每个专家在 batch 中实际被 top-k 选中的次数。如果某专家的使用频率远高于均匀分布，说明它正在"垄断"流量。

辅助损失将这两个量相乘再求和——高概率且高频率的专家贡献更多损失。最小化这个损失，就是在惩罚"赢者通吃"模式。

### 权重系数的平衡术

辅助损失的权重系数需要精心选择。**太小**意味着对负载均衡的约束太弱，可能无法阻止崩溃；**太大**则会过度强调均匀性，阻止专家发展特化能力，损害主任务性能。

经验上，0.01 到 0.1 是合理范围。选择时需要考虑：

**任务复杂度**。复杂任务可能确实需要某些专家处理更多输入，过强的均衡约束反而有害。

**专家数量**。专家越多，均匀分布的概率越低，可能需要更强的约束。

**训练阶段**。一种策略是早期使用较大权重建立均衡基础，后期减小权重允许适度的特化。

### 序列级 vs 全局级辅助损失

辅助损失可以在不同粒度上计算：

**全局级**在整个 batch 上统计专家使用，然后计算一个总的辅助损失。这种方式简单，但假设了所有样本需要类似的专家组合。

**序列级**在每个序列内独立计算均衡性，然后平均所有序列的辅助损失。这种方式允许不同序列有不同的专家偏好，更适合多样化的数据分布。

MiniMind 默认使用序列级辅助损失，这在处理多领域混合数据时更加鲁棒——不同领域的样本可以自然地依赖不同的专家子集。

## 总结与展望

SFT 是让预训练语言模型"学会对话"的关键技术，涉及从数据处理到优化策略、从单卡训练到分布式部署的全方位考量。

### 核心技术脉络

回顾全文，SFT 训练的技术栈可以归纳为几条主线：

**学习信号的精准控制**。Loss Mask 机制确保模型只从我们希望它学习的内容中学习，避免了无关信号的干扰。归一化策略让训练指标真实反映优化目标。

**优化动态的精心编排**。Warmup 提供稳定的起点，余弦退火引导优雅的收敛。梯度累积突破显存限制，梯度裁剪保障训练稳定。

**计算效率的极致追求**。混合精度训练在速度和精度间取得平衡，分布式训练实现算力的线性扩展。

**可靠性的系统保障**。检查点机制提供训练的"存档点"，使长时间训练能够承受各种意外中断。

### 从 SFT 到更远

SFT 是大模型对齐的起点，而非终点。在 SFT 的基础上，还有多个重要的技术方向：

**RLHF（基于人类反馈的强化学习）** 通过人类偏好进一步优化模型行为。SFT 教会模型"如何回答问题"，RLHF 教会模型"如何回答得更好"。

**DPO（直接偏好优化）** 将 RLHF 的两阶段过程简化为直接的偏好学习，降低了训练复杂度。

**参数高效微调（PEFT）**，如 LoRA、Adapter，用极少量参数实现微调效果，大幅降低了 SFT 的资源门槛。

**持续学习** 探索如何在不遗忘已学知识的前提下持续适应新任务，这是将 SFT 应用于真实场景的关键挑战。

理解 SFT 的原理与实践，不仅能帮助我们更好地使用现有工具，更为探索这些前沿方向奠定了坚实基础。大模型时代，训练技术的每一个细节都可能带来显著的性能差异——愿本文能为读者的探索之路提供一份有价值的参考。

# SFT 训练技术深度解析

当你拿到一个预训练语言模型，想让它学会回答问题、遵循指令或者掌握特定领域知识时，监督微调（Supervised Fine-Tuning，SFT）是你最可能采用的技术路线。然而，"微调"这个词看似简单，背后却隐藏着参数效率、训练稳定性、泛化能力等多重考量。

本文将以 MiniMind 项目中的 `my_train_sft.py` 为切入点，深入剖析 SFT 训练的核心技术。我们不仅要理解"如何实现"，更要探讨"为什么这样设计"——在模型优化与训练稳定性的博弈中，工程师们做出了哪些精妙的权衡？

> **注**：关于参数高效微调方法 LoRA 的详细解析，请参阅专门的 LoRA 技术文档。

## SFT 训练的本质与演进

### 从预训练到微调：范式的转变

大语言模型的训练遵循一个优雅的范式：**先在海量数据上预训练，再在特定任务上微调**。这个范式的成功源于一个深刻的洞察——语言的统计规律是可迁移的。

预训练阶段，模型在万亿 token 的语料上学习语言的通用表示：词汇的语义、句法的结构、上下文的依赖。这个过程需要消耗巨大的计算资源——GPT-3 的训练据估计花费了数百万美元。

微调阶段，模型在相对小规模的标注数据上学习特定任务的模式：如何回答问题、如何遵循指令、如何生成代码。关键在于，预训练获得的通用知识成为了微调的起点，使得模型能够快速适应新任务，而无需从零学起。

这种"预训练-微调"范式的效率令人惊叹。一个在通用语料上训练的模型，只需几千条对话数据的微调，就能学会以特定风格回复用户。

### 全参数微调的优势与挑战

最直接的微调方式是**全参数微调**（Full Fine-Tuning）：更新模型的所有参数，让损失函数逐步下降。

全参数微调的优势显而易见：
- **表达能力强**：所有参数都可以调整，理论上能学到任意复杂的模式
- **实现简单**：不需要额外的模块设计
- **效果上限高**：在数据充足时通常能达到最佳效果

然而，当模型规模增大时，全参数微调面临严峻的挑战：

**挑战一：显存瓶颈**

训练神经网络时，显存的占用远不止模型参数本身。以 AdamW 优化器为例，它需要为每个参数维护两个额外的状态变量：

- **一阶矩（Momentum）**：梯度的指数移动平均，用于平滑梯度方向，减少震荡
- **二阶矩（Variance）**：梯度平方的指数移动平均，用于自适应调整每个参数的学习率

这两个状态变量的物理意义是：一阶矩记录了"历史梯度的趋势方向"，帮助优化器在相同方向上加速；二阶矩记录了"历史梯度的波动幅度"，让优化器对波动大的参数使用更小的步长。

在 FP32 精度下，每个参数需要 4 字节，因此总显存占用为：

$$\text{显存占用} = \underbrace{4N}_{\text{模型参数}} + \underbrace{4N}_{\text{梯度}} + \underbrace{4N}_{\text{一阶矩}} + \underbrace{4N}_{\text{二阶矩}} = 16N \text{ 字节}$$

其中 $N$ 是参数数量。对于一个 7B 参数的模型，这意味着约 112GB 的显存——远超单卡 GPU 的容量。这还没算上前向传播时的激活值缓存！

**挑战二：灾难性遗忘**

全参数微调可能导致模型"遗忘"预训练阶段学到的知识。当微调数据与预训练数据分布差异较大时，模型可能过度拟合微调数据，丧失通用能力。这是因为所有参数都在向新任务的方向更新，没有约束来保持原有知识。

**挑战三：存储成本**

每个微调后的模型都是完整的参数拷贝。如果你需要为不同任务训练多个版本，存储成本将线性增长。一个 7B 模型的权重文件约 14GB（FP16），10 个任务版本就需要 140GB 存储空间。

这些挑战催生了**参数高效微调**（Parameter-Efficient Fine-Tuning，PEFT）的研究方向，但本文将聚焦于 SFT 的核心训练技术，这些技术无论是全参数微调还是参数高效微调都需要掌握。

## 训练数据的设计哲学

### 因果语言模型的数据格式

SFT 的第一步是准备训练数据。对于因果语言模型（Causal Language Model），核心任务是**预测下一个 token**。这决定了数据的组织方式：输入和标签错位一个位置。

考虑一个简单的例子。原始文本 "Hello world" 被分词为 token 序列 `[72, 101, 108, 108, 111]`。训练时：
- **输入**：`[<bos>, 72, 101, 108, 108]`（在开头加入起始符，去掉最后一个 token）
- **标签**：`[72, 101, 108, 108, 111]`（原始序列）

模型的任务是：看到 `<bos>` 预测 `72`（H），看到 `72` 预测 `101`（e），以此类推。

这种设计确保模型只能"向前看"，符合自回归生成的约束——生成时模型确实只能看到已生成的内容。

### 填充与掩码的必要性

批量训练时，不同样本的长度可能不同。为了组成规整的张量，需要将短序列**填充**（Padding）到统一长度。但填充位置不应参与损失计算——模型预测填充符是没有意义的。

这就引出了**掩码**（Loss Mask）的概念。掩码是一个与序列等长的 0/1 向量：
- **1**：有效 token，参与损失计算
- **0**：填充 token，损失被忽略

在 MiniMind 的实现中，掩码的构造逻辑简洁而有效：标签中非零的位置即为有效 token。这是因为填充值通常设为 0（对应 `<pad>` 或未使用的 token ID）。

### SFT 数据的特殊考量

在指令微调场景中，数据通常包含"指令"和"回复"两部分。一个常见的设计决策是：**只在回复部分计算损失**。

为什么？因为模型需要学习的是"如何回复"，而非"如何理解指令"。指令的理解能力在预训练阶段已经习得。如果在指令部分也计算损失，模型可能过度关注"如何复述指令"，反而削弱回复的质量。

实现上，只需要在构造 loss_mask 时，将指令部分标记为 0 即可。

## 损失函数与掩码机制

### 交叉熵损失：分类视角的语言建模

语言模型的训练本质上是一个超大规模的分类问题：每个位置上，模型需要从词表（通常包含数万个 token）中选择正确的下一个 token。

交叉熵损失正是为这类问题设计的。对于单个位置，假设真实 token 的索引是 $y$，模型输出的 logits 经过 softmax 得到概率分布 $\hat{p}$，则该位置的损失为：

$$\mathcal{L} = -\log \hat{p}_y$$

直观理解：如果模型对正确答案的预测概率越高，损失越低。当 $\hat{p}_y \to 1$ 时，$\mathcal{L} \to 0$；当 $\hat{p}_y \to 0$ 时，$\mathcal{L} \to \infty$。

这种"对数"形式的惩罚确保了模型不会对错误的预测过于自信——即使预测概率只有 0.01，损失也会高达 4.6（$-\log 0.01$）。

### 掩码的应用：精确控制学习目标

在 MiniMind 的训练代码中，损失计算采用了一种灵活的掩码机制。首先，使用 `reduction='none'` 模式的交叉熵损失，得到每个位置的独立损失值；然后，通过掩码进行加权平均：

$$\mathcal{L}_{total} = \frac{\sum_{i} \mathcal{L}_i \cdot m_i}{\sum_{i} m_i}$$

其中 $m_i$ 是位置 $i$ 的掩码值。

**为什么除以 $\sum m_i$ 而非序列长度？**

这是一个微妙但重要的设计。考虑两个 batch：
- Batch A：1024 个 token，50 个填充，有效 token 974 个
- Batch B：1024 个 token，500 个填充，有效 token 524 个

如果除以总长度 1024，Batch B 的平均损失会被"稀释"——同样的总损失，分母更大意味着平均更小。但这与有效 token 的数量无关，会导致训练动态不稳定：模型对填充多的 batch 学习得更"激进"。

除以有效 token 数，确保损失反映的是"每个有效 token 的平均损失"，使得不同 batch 的梯度尺度一致。

## 优化器的选择与配置

### 为什么选择 AdamW？

在深度学习发展的历程中，优化器经历了从 SGD 到 Momentum 到 Adam 再到 AdamW 的演进。每一步都是对前一代问题的修正。

**SGD 的问题**：梯度方向不稳定，容易在"峡谷"地形中震荡，收敛慢。

**Momentum 的改进**：引入动量项，累积历史梯度方向，减少震荡。但学习率仍然需要仔细调整。

**Adam 的创新**：结合动量和自适应学习率。通过一阶矩（动量）和二阶矩（方差）分别估计梯度的方向和幅度，自动调整每个参数的有效学习率。对于波动大的参数，降低学习率；对于稳定的参数，允许更大步长。

**AdamW 的修正**：Adam 的原始实现将权重衰减（Weight Decay）作为 L2 正则化项加入损失函数。但这导致权重衰减也被自适应学习率缩放，与原本的正则化意图不符。

AdamW 将权重衰减与梯度更新解耦。更新公式变为：

$$W_{t+1} = W_t - \eta \cdot \text{Adam}(\nabla \mathcal{L}) - \eta \lambda W_t$$

最后一项直接按比例缩小权重，不受自适应学习率的影响。在 Transformer 训练中，AdamW 比 Adam 更稳定，这已成为经验共识。

### 权重衰减的作用

权重衰减是一种隐式的正则化手段。它鼓励模型使用较小的权重值，防止过拟合。

直观理解：当模型拟合训练数据时，如果某些权重变得很大，权重衰减项会产生"阻力"，迫使模型寻找更"平滑"的解。这种平滑性往往意味着更好的泛化能力。

对于 SFT 任务，权重衰减还有一个额外的好处：它限制了参数偏离预训练值的程度，一定程度上缓解了灾难性遗忘。

常用的权重衰减系数是 0.01~0.1。太小则正则化效果不明显，太大则阻碍学习。

## 学习率调度策略

### 预热：温和的起步

训练初期，模型参数处于预训练状态，梯度的方向和幅度都可能不稳定。如果直接使用大学习率，可能导致参数更新过于激进，模型"跑飞"。

预热（Warmup）阶段让学习率从 0 逐渐增长到目标值，给模型一个"热身"的机会。典型的预热步数是总训练步数的 1%~10%。

预热的物理意义可以这样理解：优化器的一阶矩和二阶矩估计需要一定的历史数据才能准确。在训练初期，这些估计是基于很少的样本计算的，可能不可靠。预热给了优化器时间来积累统计信息。

### 余弦退火：优雅的收尾

预热结束后，学习率的调度策略有多种选择：恒定、线性衰减、阶梯衰减、余弦退火等。在 LLM 训练中，**余弦退火**（Cosine Annealing）已成为事实标准。

余弦退火的学习率变化曲线遵循余弦函数的半个周期：

$$\eta_t = \eta_{min} + \frac{1}{2}(\eta_{max} - \eta_{min})\left(1 + \cos\left(\frac{t}{T}\pi\right)\right)$$

这种调度的特点是：
- **前期衰减慢**：在学习率较高时保持更长时间，充分探索参数空间
- **后期衰减快**：在接近收敛时快速降低学习率，做精细调整
- **平滑过渡**：没有突变点，训练曲线更加稳定

相比线性衰减，余弦退火在训练中期保持了更高的学习率，让模型有更多机会跳出局部最优。相比阶梯衰减，它避免了学习率突变带来的训练不稳定。

## 混合精度训练

### 为什么需要低精度计算？

现代 GPU 对低精度计算有显著的硬件加速。以 NVIDIA A100 为例：
- FP32 算力：19.5 TFLOPS
- FP16/BF16 算力：312 TFLOPS（Tensor Core）

16 倍的性能差距意味着，如果能在低精度下训练，速度提升可达数倍。此外，低精度数据占用的显存也减半，允许更大的 batch size 或更长的序列。

### FP16 的挑战与 GradScaler

FP16（半精度浮点数）的表示范围较窄，约为 $6 \times 10^{-8}$ 到 $6.5 \times 10^4$。当梯度很小时（如深层网络的底层），可能会**下溢**变成 0，导致训练停滞。

PyTorch 的 `GradScaler` 通过**损失缩放**（Loss Scaling）解决这个问题：
1. 在计算损失后，将其乘以一个大的缩放因子（如 $2^{16}$）
2. 反向传播时，梯度也被相应放大，避免下溢
3. 更新参数前，将梯度除以缩放因子，恢复原始尺度

如果某次迭代出现梯度溢出（出现 inf 或 nan），GradScaler 会跳过这次更新并降低缩放因子；如果连续多次没有溢出，会逐渐增大缩放因子。这种动态调整确保了训练的鲁棒性。

### BFloat16：更稳定的选择

BFloat16（Brain Floating Point 16）是一种专为深度学习设计的数值格式。它保留了 FP32 的 8 位指数位（因此表示范围与 FP32 相同），但只用 7 位尾数（精度较低）。

相比 FP16，BFloat16 的优势是不需要损失缩放——因为不会下溢。在 A100、H100 等较新的 GPU 上，BFloat16 是更简单、更稳定的选择。

MiniMind 的实现中，默认使用 BFloat16：只有当显式指定 FP16 时才启用 GradScaler。

## 梯度累积与大批量训练

### 大批量训练的优势

深度学习的优化依赖于梯度的稳定估计。较大的 batch size 提供了更准确的梯度方向，带来几个好处：

1. **收敛更快**：每步更新的方向更准确，需要更少的迭代次数
2. **训练更稳定**：减少了梯度噪声，损失曲线更平滑
3. **更好的泛化**：某些研究表明，大 batch 训练能达到更平坦的最优解

但大 batch 也有代价：显存占用与 batch size 成正比。当 batch size 超过显存限制时，怎么办？

### 梯度累积：虚拟的大批量

梯度累积提供了一种巧妙的解决方案。核心观察是：多个小 batch 的梯度之和，等价于一个大 batch 的梯度（在期望意义上）。

具体做法：
1. 用较小的 batch 进行前向和反向传播
2. 不立即更新参数，而是累积梯度
3. 每 $k$ 步进行一次参数更新

如果每步的 batch size 是 8，累积 4 步，则有效 batch size 是 32。

**关键细节：损失归一化**

PyTorch 的 `backward()` 默认是累加梯度。如果直接累积 4 步，梯度会是单步的 4 倍。为了保持与大 batch 等价的梯度尺度，需要将每步的损失除以累积步数。

## 分布式训练

### 数据并行的基本原理

当单卡无法满足训练需求时，分布式训练是自然的选择。最简单且最常用的策略是**数据并行**（Data Parallelism）：每个 GPU 持有完整的模型副本，处理不同的数据分片，然后同步梯度。

PyTorch 的 `DistributedDataParallel`（DDP）实现了高效的数据并行：
1. 每个进程独立进行前向和反向传播
2. 反向传播时，梯度通过 AllReduce 操作在所有进程间同步
3. 每个进程独立更新参数（由于梯度相同，更新后的参数也相同）

DDP 相比 DataParallel 有两个关键优势：
- **多进程**：避免了 Python GIL 的限制
- **通信与计算重叠**：梯度同步与反向传播并行进行

### 分布式采样：确保数据不重复

在多卡训练中，确保每个进程处理不同的数据分片至关重要。`DistributedSampler` 实现了这一目标：将数据集索引平均分配给各个进程。

比如 4 卡训练时：
- 进程 0 处理索引 [0, 4, 8, ...]
- 进程 1 处理索引 [1, 5, 9, ...]
- ...

需要注意的是，每个 epoch 开始时需要更新 sampler 的随机种子（调用 `set_epoch`），否则每个 epoch 的数据顺序都相同，影响训练效果。

### 主进程控制模式

某些操作（如日志打印、模型保存）只需在一个进程执行。MiniMind 采用了标准的主进程控制模式：检查当前进程的 rank，只有 rank 0 执行这些操作。这避免了多进程同时写文件造成的冲突，也减少了冗余的日志输出。

## 训练稳定性保障

### 梯度裁剪：防止梯度爆炸

深度神经网络容易出现**梯度爆炸**：由于链式法则，梯度在层间传播时可能指数增长，导致参数更新幅度过大，训练崩溃。

梯度裁剪是一个简单有效的防护措施。最常用的方式是**范数裁剪**：计算所有参数梯度的总范数，如果超过阈值则按比例缩放。

$$g' = g \cdot \min\left(1, \frac{\text{max\_norm}}{\|g\|}\right)$$

这保持了梯度的方向，只限制其幅度。常用的阈值是 1.0。

**注意**：在混合精度训练中，裁剪必须在梯度恢复原始尺度之后进行。否则你裁剪的是缩放后的梯度，阈值的含义就变了。

### 检查点：从中断恢复

训练中断是不可避免的——硬件故障、资源抢占、手动停止都可能发生。完善的检查点机制让你能够从中断处继续训练。

一个完整的检查点应包含：
1. **模型权重**：当前的参数状态
2. **优化器状态**：一阶矩、二阶矩等中间变量
3. **训练进度**：当前 epoch、step、学习率等

**为什么要保存优化器状态？**

AdamW 的一阶矩和二阶矩是随训练逐步积累的"记忆"。如果只恢复模型权重，优化器会从零开始重新估计这些统计量，导致训练曲线不连续——表现为损失突然上升或收敛速度变慢。

### 随机性控制：可复现的实验

训练的可复现性对于调试和研究至关重要。需要控制的随机源包括：
- 模型初始化
- 数据加载顺序
- Dropout 行为
- 分布式采样

MiniMind 在训练开始时设置全局随机种子，确保在相同配置下能够复现实验结果。

在分布式训练中，每个进程需要不同但确定的随机种子（通常是基础种子加上 rank）。这确保了不同进程有不同的 dropout mask 和数据增强，同时保持可复现性。

## 总结与展望

通过对 MiniMind 项目的深入剖析，我们理解了 SFT 训练的核心技术：

### 技术要点回顾

**数据与损失**
- 因果语言模型的数据组织：输入与标签错位一个位置
- 掩码机制：精确控制哪些 token 参与损失计算
- 损失归一化：除以有效 token 数，保证梯度尺度一致

**优化策略**
- AdamW：解耦的权重衰减，更稳定的训练
- 学习率调度：预热 + 余弦退火的黄金组合
- 梯度裁剪：防止梯度爆炸的安全阀

**效率与规模**
- 混合精度：2~4 倍的速度提升，显存减半
- 梯度累积：突破显存限制，模拟大批量训练
- 分布式训练：DDP 实现高效的多卡并行

**稳定性保障**
- 检查点机制：从中断处无缝恢复
- 随机性控制：确保实验可复现

### 未来方向

SFT 技术仍在快速发展，以下几个方向值得关注：

**更高效的训练**
- 参数高效微调（PEFT）：LoRA、QLoRA 等方法大幅降低资源需求
- 序列并行：处理超长序列的分布式策略
- 量化训练：在更低精度下保持训练质量

**更好的学习策略**
- 课程学习：从简单样本到复杂样本的渐进训练
- 数据配比优化：自动调整不同数据源的采样比例
- 多任务联合训练：共享表示，提升泛化能力

**与强化学习的结合**
- RLHF：从人类反馈中学习偏好
- DPO：直接偏好优化，简化 RLHF 流程
- Constitutional AI：自我约束与对齐

SFT 是让预训练模型"学会"特定任务的关键步骤。理解其技术细节，不仅有助于有效利用现有工具，更能为未来的创新奠定基础。希望本文的分析能够帮助读者在 LLM 微调的道路上走得更远、更稳。
